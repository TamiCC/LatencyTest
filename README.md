# TCP 多线路端口延迟监测（macOS）

适用于 Apple Silicon Mac，最低系统版本为 macOS 13。

- “新建 / 开始”会根据当前状态自动操作：没有标签时直接开始第一个监测；
  当前为空白标签时开始该标签；当前已有监测任务时只创建新的空白标签。
- 点击历史记录中的“测试”时，如果同一目标已在监测，不会重复创建；程序会切换到已有标签并提示“正在监测中”。
- 多个标签同时每秒测试一次，结果、统计和停止操作互不影响。
- “停止并关闭所有标签”可一次停止并移除全部监测标签。
- 每个监测可在同一按钮位置停止或重新开始；重新开始时会清空旧结果并从第 1 次重新统计。
- 右侧的“执行 MTR”按钮可按需启动 TCP 模式 MTR；开始或重新开始 TCP 监测
  不会自动运行 MTR，因此不会反复要求管理员密码。点击后会持续更新
  TCP MTR 的路由、IP、ASN、丢包率、发送数、最近/平均/最佳/最差延迟和抖动，直到点击
  “停止 MTR”、关闭标签或退出 App。首次点击会先显示“等待响应”的路由行。
  需要时 macOS 会弹出管理员授权框，以便 MTR 创建探测套接字；取消授权只会让
  当前 MTR 显示失败，不会影响左侧 TCP 每秒监测。
- 每个标签标题右侧带有小叉，可单独停止并关闭；标签较多时可横向滚动。
- 历史目标中的 IP/域名、端口和线路备注均可直接修改。
- 搜索框直接位于“历史目标”标题同一行，可按 IP、域名、端口或线路备注即时
  筛选；点击搜索框旁的小叉可恢复全部记录。
- 可在“FTP 设置”中填写服务器、端口、用户名、密码和远程文件路径。
- 远程文件建议填写 `/targets.json`；如果使用子文件夹，需要 FTP 账号具有
  进入或创建该文件夹的权限。
- “立即同步”会先下载远程历史、合并本机与远端更改，再上传合并结果。
- “同步后关闭”只会在同步成功后退出；同步失败时程序保持打开并显示原因。
- FTP 密码保存在本机 App 设置中，下次启动会自动填写；不使用 macOS
  钥匙串，因此不会弹出钥匙串授权窗口。密码不会写入历史 JSON。
- FTP 设置界面会显示密码保存位置：
  `~/Library/Preferences/local.codex.TcpLatencyTest.plist`。
- 本地设置中的密码没有钥匙串保护，应只在可信且由本人使用的 Mac 上启用。
- 每个标签可单独停止或关闭，最多同时运行 20 个。
- 每个标签保留最近 1,000 条结果，历史目标最多保留 200 条。

历史记录保存在：

```text
~/Library/Application Support/TcpLatencyTest/targets.json
```

新版使用跨平台 JSON 格式。旧版 macOS 的数组格式会在首次启动时自动转换，
已有目标、端口和备注不会丢失。以后 Windows 版也将使用同一格式：

```json
{
  "format": "TcpLatencyTest.TargetHistory",
  "version": 2,
  "updatedAt": "2026-07-28T13:30:00Z",
  "targets": [
    {
      "id": "1E50F726-16DA-41EB-8A2F-5589B4E69D0B",
      "host": "example.com",
      "port": 443,
      "note": "示例线路",
      "lastUsed": "2026-07-28T13:30:00Z",
      "updatedAt": "2026-07-28T13:30:00Z",
      "deletedAt": null
    }
  ]
}
```

该格式使用 UTF-8、ISO 8601 UTC 时间、稳定记录 ID 和删除标记。macOS 版
通过手动 FTP 同步读取和合并同一份文件；以后 Windows 版沿用完全相同的
`targets.json` 即可互通。

> 注意：普通 FTP 不加密。建议只在可信网络中使用，并单独创建一个只能访问
> 指定同步目录的 FTP 账号。

`Release` 同时保留可直接双击的 `TcpLatencyTest.app` 和便于传输的
`TcpLatencyTest-macOS-arm64.zip`。两者是同一个程序；ZIP 解压后也是该 App。
